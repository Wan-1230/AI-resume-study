# AI Interview Prep 🎯

[![English](https://img.shields.io/badge/🌐-English-blue)](./README.md)
[![简体中文](https://img.shields.io/badge/🌐-简体中文-red)](./README_CN.md)

An interview-preparation platform focused on **AI application development roles**: RAG-powered Q&A,
question drills and mock exams, resume/JD matching. Embeddings run locally with a Chinese sentence-transformer (offline, zero API cost),
the vector store supports an in-memory backend and ChromaDB, and answers are generated by any OpenAI-compatible LLM.

> This document describes only what **actually works today**. Planned work lives in [PRD.md](./PRD.md),
> which also carries per-item progress notes.

## ✨ Features

### 🏠 Full-screen landing page
- Five-section full-page scroll: Hero → AI assistant → Resume → Question bank → About
- WebGL thread background (OGL) + GSAP scroll reveals
- Typewriter demo of the assistant

### 🤖 AI Q&A (RAG)
- **Conversations persist**: history sidebar with rename / delete / regenerate and per-answer thumbs up/down
- **Admin ships a retrieval-quality panel**: live query count, abstain rate, average latency, thumbs ratio and
  top-1 score buckets, all from `retrieval_log` (query and hit metadata only — never the answers)
- **LangChain pipeline**: load → split → embed → store → retrieve → generate
  (architecture and every environment variable: [LANGCHAIN_RAG.md](./LANGCHAIN_RAG.md))
- `Xenova/bge-small-zh-v1.5` runs inside the Node process; **once cached, the embedding stage makes no network calls at all**
- Retrieval is measured, not assumed: 60 hand-labelled cases, `hit-rate@5 73.3% / MRR 0.61` with the current model
  versus `46.7% / 0.24` with the previous default (`node backend/scripts/eval-retrieval.js`)
- Answers cite their evidence: `[1] [2]` markers map 1:1 to the source cards below the reply, click one to scroll
  and highlight it, and an audit script catches any out-of-range marker
- When nothing clears the similarity threshold the assistant says "the knowledge base has nothing on that"
  and **skips the LLM call entirely**, instead of letting the model hallucinate a confident answer
- Vector backends: `memory` (default, JSON persistence, zero external deps) and `chroma` (local ChromaDB server);
  `auto` falls back to memory when Chroma is unreachable — see [CHROMA_SETUP.md](./CHROMA_SETUP.md)
- **SSE streaming** with progressive rendering and a caret; source cards below each answer carry the similarity score
- Answers rendered as Markdown (copyable code blocks, inline code, headings, lists)
- Point at any OpenAI-compatible endpoint via `LLM_API_BASE` / `LLM_MODEL` — no code changes
- The LLM endpoint is probed at startup and `/api/health` reports `llm_status` as `ready / unreachable / disabled`;
  when generation is unavailable the UI **says so with the real reason** instead of silently passing raw retrieval results off as an answer

### 📝 Resume and JD
- Upload a resume (PDF / Word(.docx) / Markdown / TXT, or paste text) plus a job description
- Streaming rewrite with suggestions, one-click copy
- **Match report**: the JD is broken into individually checkable requirements, every "hit" has to quote the
  resume line behind it, and the score is **aggregated from those verdicts** rather than a number the model
  invents. One resume measured 77% against a RAG JD and 14% against a Java JD
- Gap rows can carry "read this next" pointers from the local knowledge base, behind a relevance gate —
  an AI-only corpus will not bolt a RAG article onto a MySQL sharding gap
- One-click `.docx` export (resume + rewrite + report), assembled in the browser so the server never stores it
- Requires login: the whole resume is sent to a third-party inference service and it is the most expensive call

### 📚 Question bank and practice
- **Practice mode**: filter by category/difficulty, answer with per-question timing, review accuracy on submission
- Options are **shuffled per session** (so nobody memorises "the third one is right"); correct answers are
  evenly distributed across A/B/C/D in the bank
- Grading happens **server-side by option text**, so tampering with the client cannot fake a score
- **Favorites**, **practice history**, **wrong-answer book** (answered correctly once = graduated) and
  **per-category mastery stats** persist in Postgres and survive refresh, restart and redeploy
- **My questions**: create / edit / delete your own questions after login; the system bank is read-only and cannot be edited away
- **Mock interview**: 6 multiple-choice + 2 open questions, the interviewer probes one level deeper based on what
  you actually said, then a debrief scores six dimensions (concepts, structure, hands-on evidence, depth/trade-offs,
  consistency, communication) with a prioritised fix list, publishable as a read-only share link
- Objective questions are graded against the bank (6,000 shuffle checks, 0 mismatches); open answers are reviewed
  but never faked into right/wrong. When generation is unavailable the debrief still ships the real objective
  score and says plainly which part did not run
- **Bulk import**: Excel / CSV validated row by row, failures reported with line numbers and reasons (nothing is silently dropped)

### 🔐 Auth and admin
- Email registration / login (bcrypt + JWT); GitHub OAuth when configured (hidden in the UI otherwise)
- Post-login JWT is handed back through a popup `postMessage` and **never travels in a URL** (browser history, proxy logs)
- Admin dashboard: search users, view details, delete, registration-source stats
- `/api/chat*` stays public for trial use but is rate-limited per IP/user with a cap on concurrent LLM calls;
  over the limit returns 429 with `Retry-After`

## 🚀 Getting started

### Requirements
- **Node.js ≥ 20** (app data lives in Postgres; see `engines` in `backend/package.json`)
- **npm** ≥ 9
- An OpenAI-compatible LLM key (optional — without it the product still runs and clearly labels
  answers as retrieval-only)

### 1. Install

```bash
npm install                 # frontend
cd backend && npm install   # backend
```

### 2. Configure

```bash
cp backend/.env.example backend/.env
```

```env
# LLM (any OpenAI-compatible service)
LLM_API_KEY=your_api_key
LLM_API_BASE=https://api.agnes-ai.cn/v1
LLM_MODEL=agnes-3.0-flash

# Vector backend: auto (default) / chroma / memory
VECTOR_BACKEND=auto

# Mirror for the first embedding-model download (no network at all once it is cached)
# HF_ENDPOINT=https://hf-mirror.com

# AI guardrails (defaults shown; sliding window per IP, or per user when logged in)
# GUARD_WINDOW_MS=60000
# CHAT_RATE_MAX=20              # questions per window
# RESUME_RATE_MAX=5             # resume optimization also requires login
# LLM_MAX_CONCURRENT=2          # in-flight LLM calls; the rest queue
# LLM_MAX_QUEUE=10              # queue full -> 503
# LLM_QUEUE_WAIT_MS=15000       # waited too long -> 503

PORT=3001
JWT_SECRET=change_me
FRONTEND_URL=http://localhost:5173

# GitHub OAuth (optional; the login button is hidden while unconfigured)
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
GITHUB_CALLBACK_URL=http://localhost:3001/api/auth/github/callback

# Single admin account, provided by env
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=your_admin_password
```

Full variable reference: [LANGCHAIN_RAG.md](./LANGCHAIN_RAG.md).

### 3. Ingest the knowledge base

```bash
cd backend
npm run ingest
```

307 documents → 661 chunks, embedded locally on CPU in roughly 2–4 minutes.
Starting the server with an empty store ingests automatically as well.

### 4. Run

```bash
# terminal 1
cd backend && npm start

# terminal 2 (project root)
npm run dev
```

Frontend at **http://localhost:5173**, health check at **http://localhost:3001/api/health**:

```json
{"status":"ok","documents_count":661,"vector_backend":"chromadb",
 "embedding":"local:xenova/bge-small-zh-v1.5","llm_model":"agnes-3.0-flash",
 "has_llm":true,"llm_status":"ready","top_k":5,"rag_engine":"langchain"}
```

## ⚠️ Known limitations

- **Upstream LLM quota**: the current endpoint is on a free rate tier; batch generation jobs compete with live
  Q&A for it (under 429 the product degrades to retrieval-only and says so)
- **GitHub OAuth happy path untested**: needs your own OAuth App before it can be verified
- **Difficulty labels not recalibrated**: ~95% of questions are still `medium`, deliberately left until real
  accuracy data exists (rationale in PRD P0-4)
- **Single-choice only**: open-ended questions with LLM grading are planned (PRD P0-4 / P1-3)
- **Rate limiting is in-process memory**: multi-instance deployments need a shared store (`backend/guard.js`)
